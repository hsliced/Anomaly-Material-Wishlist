01

The hypothesis & the constraint

Keep the player’s goal.
Change the dependency.

I began with a more ambitious idea: read the Smithy’s current requirements automatically and tell the player what to hunt. Early probes explored the game’s runtime and UI objects, but the development record describes no dependable requirement snapshot.

Waiting for that hook would have held the useful part of the experience hostage. I separated the unresolved detection work from the immediate need: record a requirement once, then keep the farming context with the player.

Evidence, with a boundary

The original v0.1.0–v0.1.2 probes survive. One result contains snapshot_count: 0, but the probe also writes an empty file on startup or clearing. It confirms an empty surviving record—not that detection was impossible.

02

Interaction model

Editing is an active task.
Remembering shouldn’t be.

The player needs quantity controls during setup and a quiet reference during play. With REFramework open, the wishlist becomes an editor. Close it, and the same saved state becomes a passive HUD.

Material labels and + add to a requirement; − subtracts. Done clears an item. F8 handles visibility. The list is manually maintained—it does not synchronize with inventory.

03

Data as product behavior

A wrong recommendation
can cost an entire hunt.

The mapping moved into an external JSON database so facts could be corrected independently of rendering. One consequential correction removed Bazelgeuse from the Dire Wing family; the preserved mapping names Gold Rathian and Silver Rathalos.

That changed how I treated the data. Material names, level ranges, and monster sources were part of the interaction’s reliability, not supporting copy. The database carries a revision; definitive external attribution remains an open documentation gap.

04

Visual iteration in context

Design beside the game,
not above it.

The Rise style borrows the game’s warm browns, gold accents, angular edges, and translucent layers. Classic remains a cyan-and-black alternative. The reference point is the native UI in a real scene, not an isolated mockup.

Testing moved the HUD lower and left beneath the Progress panels. Later, the brown wedge disappeared against a boat. The v0.6.7 pass added a dark outer silhouette, lighter type, title case, and subtle text outlines.

05

Current result & next steps

A useful milestone.
An open next chapter.

The working experience preserves a crafting need and turns it into a farming plan. Automatic Smithy detection remains future work. If it becomes reliable, the proposed interaction is a preview followed by an explicit Apply to Wishlist action, preserving the player’s control.

Further work includes border and title refinement, continued data validation, and testing across more resolutions and game contexts. No broad performance or compatibility claims are made.

Role & collaboration

Human-directed.
AI-assisted.

I defined the problem, made scope and design decisions, tested builds inside Monster Hunter Rise, supplied screenshots and runtime evidence, identified incorrect farming data, and evaluated each iteration.

AI assisted with Lua implementation, runtime exploration, debugging, data organization, packaging, and documentation. In-game validation came from my installation, testing, and feedback—not from generated code.

This story draws on surviving artifacts, historical test reports, screenshots, and a synthesis of the development conversation. Approximate early stages are identified in the evidence register. No pre-Git commits were fabricated.
